# Something new I picked up

- You can't see a password as you type it, but if the form submits with GET it appears in the URL and sits in browser history, and it isn't necessarily encrypted
- POST sends data in the request body instead of the URL, and HTTPS is what actually encrypts it in transit
- Page source and source code are not the same thing — JavaScript changes the page after it loads, so what you inspect isn't the original file
- You need a server once data has to be consistent across browsers and machines; localStorage is tied to one browser profile and disappears when cache is cleared
- The console isn't just for errors — you can run quick JavaScript in it directly, including typeof to check a data type
- Java and JavaScript are two different languages !!!

*For Step 4: deleting Number()*

Prediction: I think it will break, because an input gives back text and not a number.

What actually happened: it still gave 212. I was wrong.

After asking my agent: the `*` happens first, and `*` only works on numbers, so JavaScript turns "100" into 100 on its own. After that it is already a number, so `+ 32` adds instead of sticking text together. So Number() is not doing much here, but I would still keep it.
