# What gave me trouble, and where I'm still stuck
-   Recognizing what data a form reveals: The GET/POST demo showed a password appearing in the URL with GET. What feels harder is remembering to ask where *all* the submitted data goes, especially when a form can send it to a different site.
-   Explaining code that AI made for me: Generating the to-do app was fast, but following how an action leads to a function, changes stored data, and updates the screen seems much harder. I’d want to be able to predict what the app will do before running it.


# Something new I picked up
- When prompting with Claude, you can’t be too vague: “Babson-ish” doesn’t work
- Didn’t know search bars are forms: Google’s homepage and Babson’s search are both HTML forms
- The form’s action tells the browser where to send the search, and the input’s name determines the label attached to the search term in the URL.


# Something I noticed about working with AI this week
- Vague prompts didn’t always produce the design I had in mind. I learned that I need to describe my intent more specifically and compare different versions rather than accept the first result.
-   I noticed that AI can lose track of design choices over a long conversation. Writing them in design.md could help keep later changes consistent.
